# Design

Visual and interaction authority: the user's installed `custom-design/SKILL.md` and canonical `custom-design/design.md`, read on 13 October 2026. Preserve this product's existing ink/green identity and real source-search workflow. Do not layer competing broad design skills over this guide.

Use Space Grotesk for display and Manrope for body, packaged as local Google Fonts WOFF2 assets with OFL licenses. The existing self-only CSP takes precedence over external font loading: preload the local assets instead of adding a browser dependency on Google. The signature element is an authored structural SVG of the actual Search, Agent, Fetch workflow (Browser is an explicit alternative). This task tool does not need decorative raster photography; no ImageGen use is claimed.

Motion personality: precise. Shared easing is `cubic-bezier(.2,0,0,1)`, with 140ms feedback, 240ms state transitions and 480ms expressive timing. Preserve the existing native HTML/TypeScript host: use CSS and Web Animations rather than migrate the app to React for a design preference. Coordinate the heading, source diagram, copy and search panel entrance; animate a newly seen job once, never on each polling update. Reduced motion keeps content visible, stops spatial animation and preserves textual loading status. All controls have at least 40px targets and layouts are checked at 360, 390, 768, 1024 and 1440px.

Build an independent local TypeScript HTTP server and accessible native browser UI, named FirstStep, for students and early career developers. Preserve the existing parent app. No production canned data. A responsive sidebar, search workspace, source-check progress, saved view, and detailed evidence-backed job cards use a restrained ink/green palette.

Server owns the official TinyFish SDK, credentials, vetted employer catalog, persistent daily request counter and in-memory run state. Optional domains narrow the catalog; arbitrary remote targets are deliberately unsupported. Search discovers career URLs within those domains. TinyFish Browser mechanically navigates at most two listing pages per employer and opens only a bounded quota of linked detail pages. Optional capped Agent mode is available for accounts supporting its beta step cap. Fetch independently reads candidate source pages; only listings corroborated by that source text survive. Keywords match literal text, not invented scores. Remote geography and visa text are independent nullable fields.

Enforce up to five employers and twenty candidates, sequential execution, sixty seconds per Agent backend run, 180 seconds for its SDK response wait and eight minutes per whole run. The default Agent path reserves the documented 150-step allowance per employer before work, at a verified rate no higher than USD 0.02 per step: at most USD 3 each or USD 15 for five. Its custom step field is beta-only and omitted. Returned usage outside that default stops further work. Current wallet rates must verify free Search/Fetch and sufficient approved existing credits; unknown auto-reload, active top-ups and absent approval fail closed.

The persistent daily ledger allows forty provider HTTP requests per India-calendar day by default, configurable up to sixty-four, and thirty-two per run. SDK retries are disabled. Official Fetch robots batches contain at most ten validated public URLs; absent or failed rules block the affected source. Known Greenhouse detail aliases normalize only to the same job path on the approved current host, whose public DNS is validated. Geographic eligibility requires explicit source context rather than a bare location or application question.

Browser is an explicit alternative with a sixty-second session-creation client timeout, sixty-second watchdog, thirty-second provider inactivity fallback, GET-only interception and 300 resource requests per employer. Create and DELETE are reserved atomically. Four billed minutes per employer are reserved at a verified rate no higher than USD 0.002/minute; unconfirmed cleanup stops further sessions. Browser loops mechanically enforce two listing pages and the detail quota. Agent internal clicks, provider isolation, intermediate Fetch redirects and billing remain trust boundaries. Neither workflow automatically retries or switches to the other.
